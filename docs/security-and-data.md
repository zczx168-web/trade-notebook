# 安全与数据保护

## 已完成的防护

- GitHub 主分支启用禁止删除和强制覆盖规则；启用依赖漏洞告警、自动安全修复，增加定期依赖更新配置。
- 发布步骤固定官方 Action 提交，关闭检出凭据持久化，PR 验证仅有代码读取权限，正式发布任务才拥有 Pages/OIDC 权限。
- 发布前检查公开目录中可识别的私钥和 GitHub Token，以及依赖文件一致性。模式检查不能识别所有形式的密钥，不代表完整泄漏扫描。
- 网页 CSP 限制脚本为同源、禁止内联脚本与外连请求、禁止插件对象与表单提交；所有依赖随网站保存。浏览器脚本注入和恶意笔记测试已覆盖。允许图表所需的内联样式，因此不是最严格的样式策略。
- 本机签发资料目录已设置 Windows 文件权限，仅当前 Windows 用户与 SYSTEM 可访问；启动工具会重新应用此设置。保留原私钥，未重新生成签发身份。
- 本机开通工具依然只监听 `127.0.0.1`，检查 Host、访问凭据、Origin 和 CSRF；30 分钟无活动后需要重新打开本机启动器。

## 需要账户持有人完成

到 https://github.com/settings/security 检查并启用双重验证或通行密钥。绑定自己的验证器或安全密钥，将恢复码保存在离线位置。本次 API 没有返回可确认的双重验证状态，因此不能认定已开启或未开启。

在 GitHub 设置中检查已授权应用、访问令牌及 SSH 密钥，撤销明确不再使用的凭据；不要直接删除当前发布所需凭据。主分支保护不能阻止已控制你账号的攻击者修改仓库设置。

## 私钥与开通记录

位置：`%LOCALAPPDATA%/TradeNotebookIssuer/`。

请将 `issuer.private.pem` 和已有的 `issuer-state.json` 一起备份到由你控制的离线介质，建议介质开启 BitLocker 或使用可靠的加密备份软件。不备份运行文件 `issuer-runtime.json`。复制时不要上传到 GitHub、聊天或公共网盘。

文件权限不是加密，不能阻止在同一 Windows 账户下运行的恶意软件，也不能替代系统登录密码和磁盘加密。重装系统或更换电脑后，应恢复原私钥和完整签发记录，不能重新生成密钥替换，否则与网站公钥不匹配。具体流程见 `manual-activation.md`。

## 客户账本备份

在“账本设置 → 数据与备份”导出 JSON 文件，确认文件保存后点击“已保存备份文件”。CSV 是当前筛选结果的报表，不能替代完整 JSON。备份包含交易、分批明细、策略、笔记和账本名称；会员激活码及设备编号请另外保留。

恢复先展示预览，默认合并并保留本地同编号冲突记录；替换模式会覆盖全部交易及备份内的账本名称。编辑、删除、恢复前保留一个本机快照，可撤销或导出恢复点。快照与账本处于同一浏览器，清除网站数据仍会同时删除，应将外部备份放在浏览器之外。

新文件 SHA-256 校验用于发现意外损坏，不证明来源可信，也不会加密笔记。不要公开分享包含隐私数据的备份。旧版 JSON 仍可导入，但不具备校验码。浏览器存储不足时操作会停止，保留原账本，应先导出备份并妥善整理设备空间，不要直接清空网站数据。

## 仍然存在的边界

本地会员权限和试用期限可被修改客户端或系统时间绕过。GitHub Pages 无法通过仓库配置自定义全部响应头，本次未实现 HTTP `frame-ancestors` 防页面嵌入，也没有网络防火墙、在线撤销会员、云端备份或账户同步。后续如要求可靠付费权限或更完整响应头控制，需要后端或支持这些设置的托管平台。

未来接入后端时，先将 CSP `connect-src` 改成明确可信 API 域名，再核对账号认证、服务器权限及跨域请求；当前默认禁止外连，不能只填写 API 地址就宣称后端可用。
