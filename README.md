# 交易纠错本

基于提供的交易复盘源码整理的静态网站，面向 GitHub Pages，所有前端依赖随源码保存，无需依赖第三方 CDN。

## 当前功能

- 独立的我的账本与示例账本，真实交易记录不混入示例。
- 交易新增、编辑、删除，按日期、市场、盈亏、关键词筛选。
- 根据开仓价、平仓价、方向、手数、乘数、手续费计算净盈亏；支持直接录入净盈亏。
- 累计盈亏、胜率、平均盈亏比、最大单笔盈亏、最大日终回撤。
- 自定义错误标签、错误分布、关联亏损、Top 3 改进建议、开仓理由与复盘笔记。
- CSV 导出、JSON 完整备份与恢复，中文复盘报告可通过浏览器打印保存为 PDF。
- 月度会员 19.90 元 / 30 天、永久会员 199 元的独立微信收款码，支持查看和下载原图。
- 微信客服二维码与人工核账入口；不会因打开二维码或联系客服而标记支付成功、开通会员。
- 本机会员开通工具：人工核账后签发设备绑定的激活码，支持月卡续费、永久会员与历史发码查询。
- 主动领取 7 天免费试用，开放全部会员功能，显示剩余天数与到期时间，到期保留账本并恢复基础权限。
- 登录、注册、密码找回及自动支付的前端接口边界；尚未连接服务器，不假装发送短信或确认到账。

## 本地打开

直接打开 `site/index.html`。不需要运行开发服务器。

数据存放在当前浏览器的 localStorage。`file:`、本地 HTTP 和 GitHub Pages 是不同的存储环境，切换环境时请通过 JSON 备份迁移。不会将账本内容提交到 GitHub。清除浏览器数据会丢失记录，备份文件包含交易笔记，请妥善保存。

首次没有个人交易时显示带明确标签的示例账本。新增交易会切换到我的账本。基础记账、基础统计、CSV 和备份免费；个人盈亏图表、错误分析和完整打印报告需要会员，示例账本可免费预览这些功能。正式使用激活功能请访问 HTTPS 网站。

## 人工开通会员

客户可在会员中心或受限功能页点击“免费试用 7 天”，无需付款或客服签发。有效期从领取时起连续计算 168 小时，刷新与同一浏览器的其他标签页保持一致，不自动扣费。正常使用时每个浏览器限领一次。试用记录保存在本地，清除存储、换浏览器或修改系统时间可以绕过限制；当前无法保证每人仅一次。付费会员优先，付费期限独立计算，不叠加剩余试用时间。试用到期不删除交易数据。

客服已配置为运营方提供的“焦煤观察”微信二维码。客户付款后发送付款凭证、会员类型和本站设备编号；运营方核实微信实际到账，再双击项目目录中的 `会员开通工具.cmd`，填写设备编号、会员类型、微信交易单号并确认签发。将生成的客户消息或激活文件发给客户，客户在网站“会员中心 → 激活会员”验证即可开通。

操作、续费与备份说明见 [会员开通操作说明](docs/manual-activation.md)。工具仅在本机运行，需要 Node.js；它不是 GitHub Pages 上的管理后台。私钥与发码记录存放在 `%LOCALAPPDATA%/TradeNotebookIssuer/`，不会提交或发布到 GitHub。请保留并离线备份原私钥，不要重新生成替换。

## 验证与依赖

```powershell
npm ci
npm run vendor
npm test
npm run test:browser
```

浏览器测试使用本机 Chrome，覆盖 1440、768、390、320 像素视口、图表像素、增删改、做空盈亏、刷新保存、筛选、导入导出、中文报告和未配置服务状态。生成的截图和测试 PDF 保存在被 Git 忽略的 `test-results/` 中。

`npm run test:payments` 单独验证两档微信收款码、金额对应、原图下载、客服入口、手机布局、图片失败提示，以及不会生成支付成功或会员权益。

`npm run test:activation` 使用隔离测试密钥验证本机签发、客户激活、刷新保持、过期、篡改、设备不匹配、报告权限及手机布局，不签发生产会员。`npm test` 还验证续费、重复交易单号、永久权益保护和本机管理接口访问控制。

`npm run test:trial` 验证主动领取、重复领取限制、刷新与多标签页、精确到期、到期保留数据、付费权益优先、异常存储和桌面手机布局。设置 `TEST_URL` 可检查线上版本。

## 发布到 GitHub Pages

```powershell
pwsh -File scripts/deploy.ps1
```

脚本优先使用已登录的 GitHub CLI，再尝试 Git Credential Manager 中已有的 GitHub 凭据。凭据只传给当前进程的 GitHub CLI，不写入源码、不输出密钥。没有现成登录时会提示先执行 `gh auth login --web --scopes workflow`。

脚本创建当前账号的公开仓库 `trade-notebook`，启用 GitHub Actions Pages 部署并推送当前提交。若同名仓库已经存在且不是当前项目的远端，会停止，避免覆盖其他项目。`.github/workflows/pages.yml` 会在 `main` 更新时运行测试并发布 `site/`，不会发布测试输出、node_modules 或交易数据。

## 短信、账号与支付

当前公开版使用运营方提供的固定微信收款码，月度和永久会员使用各自对应的图片，金额分别为 19.90 元、199 元。原图保存在 `site/assets/payments/`，浏览器展示从原图裁出的二维码区域，保留完整码点、中心图案及四周空白；保存和查看原图使用未经修改的 JPG。

实际支付发生在微信中，网站没有支付接口，不能确认是否付款。用户通过客服微信发送付款凭证与设备编号，运营方核账后使用本机工具签发激活码。网站不上传凭证、不建立假订单，只有验证激活码后才更新当前浏览器的会员状态。月卡从签发时起算 30 天，续费从当前时间与原到期日中较晚者顺延；同一交易单号重复签发只返回原码。

GitHub Pages 不运行服务器，也无法接收支付异步通知。当前未部署账号服务器、数据库、短信服务或自动支付网关，短信登录与自动开通仍不可用。完整接入要求见 `docs/backend-contract.md`。

只在 `site/config.js` 填写公开的 HTTPS API 地址和收银台域名白名单。商户 ID、商户密钥、短信凭据应由服务器配置，不得写到网页或 GitHub 仓库。前端不保存密码、不校验模拟验证码、不信任 localStorage 中的会员标记、不通过支付回跳参数开通会员。

提供源码中的调试开通按钮已移除；做空盈亏方向已修正；报告使用浏览器中文字体并保留完整笔记，避免默认 PDF 字体乱码与笔记截断。

数字签名可检测激活码内容篡改，但所有功能仍在客户端执行，修改网页代码、设备编号或系统时间可以绕过限制；不能等同于服务端付费权限。没有跨设备账号同步、在线撤销或退款自动停权。更换设备不支持自助迁移，客服应事先与客户确认处理安排。
